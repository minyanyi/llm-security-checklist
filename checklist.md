# AI/LLM Security Checklist (OWASP LLM Top 10 2025)

Use this checklist when building, deploying, or auditing any LLM-powered application.

---

## LLM01: Prompt Injection

- [ ] System prompt is isolated from user input (not concatenated)
- [ ] Input filtering detects injection patterns ("ignore previous", "you are now")
- [ ] Output validation strips system-level content before returning to user
- [ ] Multi-turn injection tested (payload split across messages)
- [ ] Indirect injection tested (malicious content in RAG documents, tool outputs)
- [ ] Privilege separation: LLM cannot execute actions without user confirmation
- [ ] Jailbreak resistance tested (DAN, role-play, encoding tricks)

## LLM02: Insecure Output Handling

- [ ] LLM output is sanitized before rendering in HTML (XSS prevention)
- [ ] LLM output is parameterized before SQL/NoSQL queries
- [ ] LLM output is validated before passing to system commands
- [ ] Markdown/HTML rendering strips script tags and event handlers
- [ ] Output used in emails/templates is escaped

## LLM03: Training Data Poisoning

- [ ] Training data sources are verified and access-controlled
- [ ] Fine-tuning pipelines validate data integrity (checksums)
- [ ] Adversarial examples tested against model
- [ ] Data provenance tracked for all training sets
- [ ] Model behavior monitored for drift/anomalies post-deployment

## LLM04: Model Denial of Service

- [ ] Rate limiting enforced per user/IP/API key
- [ ] Max token limits set on all completion requests
- [ ] Timeout configured for long-running inference
- [ ] Resource quotas prevent single-user exhaustion
- [ ] Streaming responses can be cancelled mid-generation
- [ ] Input length validation rejects oversized prompts

## LLM05: Supply Chain Vulnerabilities

- [ ] Model weights verified (hash check against source)
- [ ] Third-party plugins/tools vetted before integration
- [ ] Dependencies scanned for known CVEs
- [ ] Model registry access is authenticated and audited
- [ ] CI/CD pipeline for model deployment is secured

## LLM06: Sensitive Information Disclosure

- [ ] System prompts not leakable via injection
- [ ] API keys/secrets not in model context or training data
- [ ] PII detection in model outputs (before returning to user)
- [ ] Logging does not capture full prompts/completions with PII
- [ ] Error messages don't expose internal architecture
- [ ] .env / config files not publicly accessible

## LLM07: Insecure Plugin/Tool Design

- [ ] Tool inputs validated and sanitized (no raw user input to tools)
- [ ] Tool execution sandboxed (no arbitrary code execution)
- [ ] URL-accepting tools block RFC 1918 / link-local / metadata IPs
- [ ] File-accessing tools restricted to allowed directories
- [ ] Tool results validated before feeding back to model
- [ ] Least privilege: each tool has minimal required permissions

## LLM08: Excessive Agency

- [ ] LLM cannot take irreversible actions without human approval
- [ ] Function-calling limited to explicit allowlist
- [ ] Autonomous agents have kill switches and action budgets
- [ ] Financial/transactional actions require confirmation
- [ ] Agent memory/context cannot be manipulated to escalate privileges

## LLM09: Overreliance

- [ ] Critical decisions have human-in-the-loop
- [ ] Model outputs labeled as AI-generated where required
- [ ] Fallback behavior defined for model failures
- [ ] Accuracy monitoring with ground-truth validation
- [ ] Users informed of model limitations and confidence levels

## LLM10: Model Theft

- [ ] Model API access authenticated (no anonymous inference)
- [ ] Rate limiting prevents model extraction via bulk queries
- [ ] Model weights encrypted at rest and in transit
- [ ] Access logs for model inference (detect extraction patterns)
- [ ] Watermarking or fingerprinting for stolen model detection

---

## Bonus: Infrastructure

- [ ] HTTPS enforced (HSTS header present)
- [ ] CORS restricted to trusted origins
- [ ] Admin endpoints behind authentication
- [ ] Webhook endpoints validate signatures
- [ ] Secrets rotated regularly
- [ ] Dependency updates automated (Dependabot/Renovate)
